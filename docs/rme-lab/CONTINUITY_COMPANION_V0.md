# RME Continuity Companion — V0

**Status:** LAB / hypothesis, not production.

## The idea

The strategic constraint is the **small-prompt test**:

> If a general AI can reproduce a feature with a short prompt, the feature is not a defensible RME advantage by itself.

The proposed counter-principle is not “a better chatbot”. It is **persistent journey continuity**:

`INTENTION → STATE → CHANGE → UNCERTAINTY → NEXT ACTION → NEW STATE`

RME should remain silent when no change affects the next decision.

## Why this is different

A generic assistant can answer:

> “I am in Algeciras, I have my family and my ferry tomorrow. What should I do?”

The RME hypothesis is stronger only if it can retain that journey state across time, compare the current state with the previous state, and surface a useful action without forcing the traveller to reconstruct the context.

This connects previously retained RME primitives:
- Intent Engine
- Journey State
- Question Value Gate
- Trajectory State
- Reality Check
- Action Cards
- Journey Moment / temporal context

## Zero-euro constraint

V0 uses no paid API, no new account, no production database, no secret, and no external AI call. It is a deterministic visual lab.

## Validation gate

Do **not** call this a moat or a validated product advantage yet.

The next proof must compare:
1. short-prompt general AI response;
2. stateless RME response;
3. stateful RME continuity response.

Measure whether continuity reduces repeated questions/searches and whether users actually prefer the resulting action flow.

A future production version should only be considered after real-user evidence.

## Protected scope

This lab must not modify production behavior, affiliate configuration, mobile release artifacts, or the protected Master Control branch.
