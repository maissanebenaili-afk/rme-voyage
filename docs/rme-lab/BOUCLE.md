# Boucle de travail autonome (Claude, toutes les 3 heures)

Ce fichier est le mode d'emploi de la boucle.

Fonctionnement : une session Claude dédiée, avec le dépôt attaché (modèle économe), est réveillée **toutes les 3 heures** par une Routine. Les sessions neuves lancées par une Routine n'ont pas d'accès en écriture à GitHub (essai du 5 octobre : arrêt au bout de 20 s), d'où la session dédiée. La limite d'usage hebdomadaire du compte est presque atteinte : chaque passage doit rester court. Son but : faire avancer RME Voyage sans que Tarek serve de relais entre ChatGPT et Claude. Les règles de `CLAUDE.md` passent avant tout ce qui suit.

## Canal avec ChatGPT
- **PR ouverte en cours** (au 5 octobre 2026 : **#253**). C'est là que passent les consignes et les preuves, tant qu'elle n'est pas fusionnée.
- **Ticket #232** (« PARALLEL CONTROL PLANE ») : canal permanent, y compris après la fusion.
- Format de chaque compte rendu : `STATUS / COMMIT / TESTS / BUILD / SMOKE / PROD-PREVIEW / REMAINING` (3 points au plus).
- Ne commenter que s'il y a du nouveau. Jamais de « rien à signaler ».

## À chaque passage, dans l'ordre
1. **Lire l'état réel** :
   - les PR ouvertes des branches `claude/*` (CI, conflits, commentaires) ;
   - les nouveaux commentaires de #232 ;
   - l'état de la production : si `https://rme-voyage.netlify.app/pitch` contient encore « 2100 km », c'est l'ancien build.
2. **Consignes de ChatGPT pas encore traitées** : ce sont les commentaires **sans** pied « Generated by Claude Code », postés après le dernier compte rendu de Claude.
   - Si la consigne est petite, sûre et dans le périmètre : l'exécuter, la valider, pousser, puis rendre compte.
   - Sinon : répondre en une ligne pourquoi elle n'est pas faite.
3. **CI rouge ou conflit sur une PR `claude/*`** :
   - trouver la cause et corriger ;
   - fusionner `main` dans la branche, sans jamais réécrire l'historique ;
   - valider (`npx tsc --noEmit`, `npx eslint .`, `npx jest`, `next build --webpack`) avant de pousser.
4. **Production publiée** (plus de « 2100 km » sur `/pitch`) :
   - lancer `prodcheck.js` et `parcours-v2.js` sur `https://rme-voyage.netlify.app` ;
   - poster le résultat dans #232.
5. **Rien d'autre à faire** : s'arrêter. Pas de nouvelle PR sans bug bloquant ou risque de vérité démontré (une hypothèse = un test = une mesure).

- Les adresses en `https` passent par `$HTTPS_PROXY`.
- La limite de Hadak est de 8 requêtes par minute et par adresse IP : `prodcheck` espace ses questions de 9 s.
